# 검증 범위와 현재 한계

## 초기 정리본 확인

2026-10-20, Windows/Python 3.11.9에서 다음을 확인했습니다.

- 새 가상 환경에 핵심 패키지만 설치해 PyTorch 없이 캐시 기반 영상 처리 및 UI 재생성 성공.
- 단위/통합 테스트 60개 통과. 합성 영상의 전체 프레임 수, 평균 FPS, 출력 해상도와 H.264 재생 확인 포함.
- 기존 코드와 10개 캐시 장면의 경계 마스크·중심 경로가 동일.
- 기존 전체 영상의 5,289개 방향 투표 상태가 동일.
- 기본 상단 UI의 대표 5개 화면이 기존 코드와 픽셀 단위로 동일.
- 기존 `small.pth`와 로컬 SegFormer 캐시를 사용해 CPU 실제 추론 6프레임 및 MP4 출력 성공.
- Ruff 검사와 포맷 검사 통과.

CPU 추론 환경은 기존에 검증한 PyTorch 2.14.1+cpu / Transformers 4.57.6입니다. GPU 실행은 이 환경에서 검증하지 않았습니다. 일부 기존 SegFormer 전처리 설정 이름이 무시된다는 Transformers 경고가 나타났지만 추론은 완료됐습니다.

## 스티어링 UI 추가 이후

- 초기 정리본을 먼저 push한 다음 별도 변경으로 추가했습니다.
- 테스트는 총 66개이며 모두 통과했습니다. 좌·우 부호, 급격한 반전 제한, 반대 후보 무시, 추적 프레임과 새 관측 구분, 관측 만료, 휠 그림 회전 검사를 포함합니다.
- 경로/도로 추론은 바꾸지 않고 저장된 5,289프레임의 관측 정보로 UI를 다시 생성하고 360×640, 88.19초의 전체 5,289프레임 디코딩을 확인했습니다.
- 초기 정리 당시의 픽셀 동일성 검사는 0.1.0 UI를 대상으로 했습니다. 0.2.0은 스티어링 그림과 글자가 의도적으로 달라집니다.

## 기존 영상 실험의 의미

패키지 정리 이전에 88.19초/5,289프레임의 도로 영상을 360×640, 원본 평균 FPS로 처리했습니다. 이 영상과 마스크는 저장소에 배포하지 않습니다.

고정된 기준 장면 8장의 방향 일치는 반복 사용한 진단 사례의 회귀 결과입니다. 독립 검증셋의 정확도가 아닙니다. 짧은 표시 전환이 줄었다는 통계도 전환 지연과 함께 평가해야 합니다.

## 남은 한계

- 차선과 최근 차로 이력이 없으면 도로 전체를 현재 차로 하나로 확정할 수 없습니다. 화면의 `도로 중심 추정` 상태는 이 한계를 나타냅니다.
- 추정 경계 안에 경로가 있다는 검사는 실제 차로 경계 준수의 정답 검증이 아닙니다.
- 중심 편차는 추정한 가시 영역의 중심에 대한 값입니다. 카메라에 보이지 않는 경계나 실제 차량 중심을 측정한 값이 아닙니다.
- 영상 내 경로와 굽힘/방향각은 지면 보정이나 차량 모델을 사용한 실제 조향 명령이 아닙니다.
- 캐시가 해당 원본과 동일하다는 사실을 프레임 개수만으로 검증할 수는 없습니다.
- 기본 원본 평균 FPS 모드는 전체 프레임을 유지하지만 가변 FPS 영상의 개별 타임스탬프를 재현하지 않습니다.
- 검출 지지율과 연속 관측은 통계적으로 보정된 정답 확률이 아닙니다.
